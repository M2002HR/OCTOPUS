# Private Telegram messaging assistant

## Scope and access control

The persistent `serve` process also receives private Telegram messages. It accepts only the
startup-resolved numeric identity configured by `VOICE_AGENT_MESSAGE_USERNAME`; every other
private message is ignored. This is independent of display names and prevents a renamed account
from gaining access.

Inputs are handled as follows:

| Input | Processing |
| --- | --- |
| Text | Ajil conversation request |
| Voice note or audio attachment | Downloaded temporarily, transcribed by Ajil STT, then sent to Ajil chat |
| Photo or image attachment | Downloaded temporarily and supplied to Ajil as an OpenAI-compatible data-URL image part; the pinned Ajil Gemini adapter maps this to inline image data |
| Video or document | Safely downloaded for audit/size validation; its caption is processed as text. Frame-level video analysis is intentionally not claimed because the configured Ajil contract does not upload video files to a vision API. |

## Replies and quoted context

When the user replies to an earlier Telegram message, that referenced message is included in the
new request context. Referenced text and captions are labelled as quoted context; referenced photos
are sent together with any new photo to the configured vision model; and referenced voice notes or
audio attachments are downloaded temporarily and transcribed through Ajil STT before being added to
the context. A referenced video/document contributes its caption only. The new message—not the
quoted one—controls `/voice` or `/text` response mode.

The same size limit applies independently to the quoted attachment. Missing, oversized, or
unavailable quoted media is recorded in a content-free `message.reply_context.*` audit event and is
not sent to a model. Temporary quoted files are deleted with the rest of the turn data.

Incoming media and generated voice replies are deleted once delivery finishes. With
`VOICE_AGENT_RECORDING_MODE=transcript_only`, text inputs/transcripts, replies, selected response
mode, and sent library asset IDs are persisted in SQLite `message_turns`; JSONL events remain
content-free.

## Text-first replies, language, and voice

`VOICE_AGENT_MESSAGE_DEFAULT_RESPONSE=text` is the default. `/voice <request>` explicitly requests
an Ogg/Opus voice note generated by Edge TTS; `/text <request>` forces text. The assistant is
instructed to match the input language and not to introduce itself or an artificial persona unless
the user explicitly asks. Voice-note STT uses automatic language detection by default.

`EDGE_TTS_VOICE` is the male fallback voice. `EDGE_TTS_VOICE_BY_LANGUAGE` maps detected response
scripts to male voices. The supplied defaults cover Persian/Sorani fallback, Arabic, Turkish, and
English. Edge TTS does not currently list a dedicated Kurdish voice, so Sorani text uses the
configured Persian male fallback unless an operator supplies a different compatible voice.

## Local image and video sending

The assistant does not generate images or video. It can send only approved existing files listed
in `VOICE_AGENT_MESSAGE_MEDIA_MANIFEST`, whose paths must remain inside
`VOICE_AGENT_MESSAGE_MEDIA_LIBRARY_DIR`. Copy [media-library.example.json](media-library.example.json)
to the configured manifest path, place the referenced files in that same directory, and edit the
IDs/captions. Do not put secrets in the manifest.

Ajil receives the catalog as context. If it determines that a listed asset is appropriate, it emits
an internal `[[send_media:ASSET_ID]]` directive; the agent strips that directive before answering
and sends the matching local file. Unknown IDs, missing files, path traversal, or unlisted files
are rejected and never sent.

## Configuration

| Variable | Default | Meaning |
| --- | --- | --- |
| `VOICE_AGENT_MESSAGE_ENABLED` | `true` | Enables the message handler inside `serve`. |
| `VOICE_AGENT_MESSAGE_USERNAME` | inbound username | Sole private-message sender; resolved and allowlisted at startup. |
| `VOICE_AGENT_MESSAGE_DEFAULT_RESPONSE` | `text` | `voice` or `text`. |
| `VOICE_AGENT_MESSAGE_MAX_MEDIA_BYTES` | `12582912` | Maximum accepted incoming voice/photo/video/document size. |
| `VOICE_AGENT_MESSAGE_MEDIA_LIBRARY_DIR` | `media-library` | Local root for assets the assistant is allowed to send. Relative paths are resolved inside `RUNTIME_DIR`. |
| `VOICE_AGENT_MESSAGE_MEDIA_MANIFEST` | `media-library/manifest.json` | JSON allowlist for sendable image/video assets. Relative paths are resolved inside `RUNTIME_DIR`. |
| `VOICE_AGENT_MESSAGE_VISION_ENABLED` | `true` | Enables photo-to-Ajil vision requests. Disable it to process a photo caption as text only. |
| `VOICE_AGENT_MESSAGE_STT_LANGUAGE` | empty | Optional STT language hint; empty enables automatic detection for voice notes. |
| `VOICE_AGENT_VISION_MODELS` | `gemini/gemini-2.5-flash` | Comma-separated vision-capable Ajil model IDs; independent of text-chat models. |
| `VOICE_AGENT_VISION_PROVIDERS` | `gemini` | Comma-separated Ajil providers allowed for image analysis. |

## Verification

Run the automated suite, then start the persistent stack:

```bash
.venv/bin/pytest -q
docker compose --profile agent up -d --build
docker compose logs -f voice-agent
```

From the configured account, send: plain text, `/text` plus a request, a voice note, a photo with
a question, and a request that matches a media-library asset. Confirm audit event sequences in
`runtime/events.jsonl` and transcript rows in SQLite only when authorized.
